# naarm.lc
live coders naarm are a community of live coders in Melbourne, Australia

## Development

Uses [Bun](https://bun.sh), [Astro](https://docs.astro.build) with Svelte, and [Neon](https://neon.com) Postgres.
Most pages are static; login, profiles, events and the doorway render on demand on Netlify.

```sh
bun install
cp .env.example .env.local   # then fill it in, see below
bun run db:migrate           # create the tables on your branch
astro dev --background       # http://localhost:4321
```

### Environment

Every variable is described in `.env.example`. Locally you need the database URLs, `BETTER_AUTH_SECRET`,
`BETTER_AUTH_URL` and a Discord app of your own (redirect `http://localhost:4321/api/auth/callback/discord`).
Without Resend set up, email login links are printed to the dev server log (`astro dev logs`).

### Database

The Neon project has three branches:

| Branch       | Used by                   |
| ------------ | ------------------------- |
| `production` | the live site             |
| `preview`    | Netlify deploy previews   |
| `dev`        | local development         |

Link your checkout to `dev` with `npx neon@latest checkout dev`, which also writes its connection strings to `.env.local`.

Tables are defined in `src/lib/schema/`. `auth.ts` there is generated by Better Auth's CLI, so don't edit it by hand.
After changing a schema file:

```sh
bun run db:generate   # writes a migration to drizzle/
bun run db:migrate    # applies it to the branch in .env.local
```

Migrations aren't run automatically on deploy. To apply them to another branch, pass its direct (unpooled) connection string:

```sh
DATABASE_URL_UNPOOLED="$(npx neon@latest connection-string preview)" bun run db:migrate
DATABASE_URL_UNPOOLED="$(npx neon@latest connection-string production)" bun run db:migrate
```

Run them on `production` before merging a change that needs them.

### Admins

Admins manage events at `/admin/events` and run the doorway at `/admin/doorway`. To make someone an admin
(on whichever branch `.env.local` points at):

```sh
bun run make-admin <email or username>
bun run make-admin <email or username> --remove
```

For the live site, point it at `production` (the person must have logged in there once first):

```sh
DATABASE_URL="$(npx neon@latest connection-string production)" bun run make-admin <email or username>
```
